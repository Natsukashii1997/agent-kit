# 机器执行层：权限规则、hook、agent-kit 自检、每周汇总

来由：[2026-11-05 最佳实践对照报告](research/2026-11-05-best-practices.md)的结论是：「写给人和模型读的规矩」已经够严，缺的是「到了关键时刻机器一定会执行」的那一层。这里把 5 件事落成可安装的文件。

报告第 5 节的本机核对发现，第 3 件（体检）、第 4 件（会话复盘）在 my-skills 里已经有同日自建的实现：`automation-checkup`（my-skills#30）、`session-retro`（my-skills#28）。所以这里**不再重复做**它们：
- launchd、Hermes 定时任务、crontab 的体检，归 automation-checkup。
- 会话复盘归 session-retro。
- 本仓库只做它们不覆盖的：agent-kit 自己装进本机的东西装没装好、两份全局指令是否一致、坑提醒的命中统计。

> 术语：
> - **hook**：Claude Code / Codex 在固定时刻（这里是「执行命令或改文件之前」）一定会跑的小脚本，不靠模型自觉。你本机已有的 9 个和 7 个 hook 都不在这个时刻，和这里加的不冲突。
> - **权限规则**：设置文件里的一行，写明哪类命令「直接拒绝」或「先问我」。
> - **状态目录**：本机存提醒日志、自检报告的地方。macOS 上是 `~/Library/Application Support/agent-kit/`，不放 `/tmp`（G-01）。

## 一次装好（在本机终端里，约 2 分钟）

这个 PR 合并、主目录拉齐后，在 agent-kit 目录里依次跑：

```bash
node tools/install.mjs
```

先看预览，它会列出要改哪几个文件、加什么，**这一步不写任何文件**。确认没问题再跑：

```bash
node tools/install.mjs --apply
```

装完后，**新开**的 Claude Code / Codex 会话才生效。Codex 第一次可能会请你确认是否信任这两个 hook（未实测）。最后核对一遍：

```bash
node tools/doctor.mjs
```

- 会改的文件：
  - `~/.claude/settings.json`：加 `permissions.deny`、`permissions.ask` 和 2 个 hook。
  - `~/.codex/hooks.json`：加 2 个 hook。
  - `~/.codex/rules/agent-kit.rules`：Codex 的「禁止 / 先问」规则。
- 每个文件写之前都备份成 `原文件名.bak-agent-kit-<时间>`。你原有的设置和 hook（会话命名、交接提醒、PostPane 通知等）原样保留。
- 装之前会先让两个 hook 各跑一次自检，没通过就什么都不改。
- 卸载：`node tools/install.mjs --uninstall --apply`，只去掉 agent-kit 加的东西。
- 只装一边：加 `--only claude` 或 `--only codex`。

## 第 1 件：不可逆操作，机器把关

| 操作 | Claude Code | Codex |
|---|---|---|
| 强推到 main/master（含 `--force-with-lease`、`+main`），或删除远端 main/master | **直接拒绝**：权限规则 deny，加 hook 兜底 | **直接拒绝**：执行策略 forbidden，加 hook 兜底 |
| `gh pr merge` | 先问你 | 先问你 |
| 推 main/master（`git push origin main`） | 先问你 | 先问你 |
| 强推分支（`-f` / `--force`） | 先问你 | 先问你，`--force` 写在前面时才问到，见下 |
| 删除远端分支、`git reset --hard`、`git clean`、`git branch -D`、`git stash drop/clear` | 先问你 | 先问你 |
| `--force-with-lease` 推自己的分支 | 放行（《工程流程》第 5 节第 3 步允许） | 放行 |

- **为什么拒绝用两层**：官方文档说 hook 出错时默认放行，所以硬红线以权限规则为准。但权限规则只认固定写法，像 `git -C 目录 push`、参数顺序打乱这类写法认不出来，这些交给 hook [hooks/guard-git.mjs](../hooks/guard-git.mjs) 兜住。
- 规则文件：
  - Claude：[config/claude-permissions.json](../config/claude-permissions.json)。官方文档写明 ask 规则在自动模式下也会弹窗，`cd x && git clean -f` 这样拼在一起的命令也会问。
  - Codex：[config/codex/agent-kit.rules](../config/codex/agent-kit.rules)。
- 已核实：
  - Codex 规则已用 Codex 0.166.0 的 `codex execpolicy check` 实测 11 个命令，结果都符合上表。本机装了 codex 时，`tests/codex-rules.test.mjs` 会自动再测一遍。
  - guard-git 有二十多个命令样例的测试。
- 没核实：没在真的 Claude Code 里实装跑过（云端会话改不到你本机的设置），Claude 的 deny / ask 规则是照官方文档的写法写的。**装完请验一次**：在任意仓库里让 Claude 执行 `git push --force origin main`，应该被拒绝、命令不会真的执行；再让它执行 `gh pr merge`，应该弹窗问你。
- 已知漏洞：
  - Codex 的规则只认开头几个词，`git push origin feature --force` 这种把 `--force` 写在最后的不会问。
  - `git -C 其他目录 push origin main` 这种写法，两边的「先问」都认不出来。但只要带强推、推的是 main，照样被拒绝。
  - **Hermes 不受这套约束**：它的派单靠什么兜底，要你另外定。
- 关于本机已装的 `git-guardrails-claude-code` skill：它是 Matt Pocock 用来「设置拦危险 git 命令的 hook」的技能。按我对它的了解，它会把 `git push` 整个拦掉，而各会话推分支开 PR 是日常操作，所以建议不要再用它装一份。这只是基于我的了解，没读你本机那一版，要核对一下。

## 第 2 件：LESSONS 按关键词提醒

- LESSONS 每条 G-xx 末尾新加了一行「触发：」，写的是碰到这条坑时命令或代码里会出现的词。
- hook [hooks/lessons-remind.mjs](../hooks/lessons-remind.mjs) 在执行命令、改文件之前比对这些词，命中就把那条坑的标题和「正确做法」的第一句提示给模型。例如命令里有 `launchctl` 时，会提示 G-05 和 G-18。
- 它只提醒、从不拦截；同一会话里同一条只提醒一次。
- 每次命中都记一行到状态目录的 `lessons-hits.jsonl`。这是 automation-checkup 和 session-retro 都没有的数据：哪条坑在实际工作中被碰到几次、在哪些项目。
- 「触发」词怎么写，见 LESSONS 开头「怎么写」。词太宽会天天误报，这时就收窄。G-09（界面改动）想不出可靠的词，写了「无」。

## 第 3 件：本机体检 = automation-checkup（my-skills#30）+ agent-kit 自检

- **launchd、Hermes 定时任务、crontab**：用 my-skills 的 automation-checkup。合并 my-skills#30，按需定时跑。
- **agent-kit 自检**：
  ```bash
  node tools/doctor.mjs
  ```
  不用配置就会查：
  - Claude、Codex 的拒绝 / 先问规则和 2 个 hook 装没装。
  - 两个 hook 能不能**按设置里写的那条命令**真的跑起来。hook 坏了默认放行，平时看不出来；比如 Homebrew 升级 node 后路径变了，这一步会报 ✗。
  - 两份全局指令里「跨项目沉淀」那一节是否逐字一致（第 5 件）。
  - Claude 自动记忆开没开。
  - 近 7 天哪些坑被提醒过。
- 可选配置：复制 [tools/doctor.example.json](../tools/doctor.example.json) 到 `~/Library/Application Support/agent-kit/doctor.json`，填上 `repos`，就会顺带查各仓库本地 main 有没有别的会话留下的、没推的提交（《工程流程》5.1）。
- 报告存在状态目录的 `doctor/` 下：第一行是开始时间，最后一行是 `exit N`（G-12 的写法），最多保留 60 份。有 ✗ 时退出码为 1。
- 要不要定时跑：可以并进 automation-checkup 的定时任务里一起跑。不要单独用 launchd 跑：agent-kit 放在「文稿」目录下，launchd 直接启动的程序读不了「文稿」（G-05）。

## 第 4 件：会话复盘 = session-retro（my-skills#28）+ 每周汇总

- 会话复盘用 my-skills 的 session-retro：纯本地、只出提案、片段脱敏。报告原来建议的第三方工具 sheal 不用了。
- 每周整理时再跑：
  ```bash
  node tools/weekly-review.mjs
  ```
  它把 agent-kit 自检结果和近 7 天坑提醒命中统计（按条、会话数、项目）汇成一份 Markdown，存到状态目录的 `weekly/<日期>.md`，并打印文件路径。
- 把它和 session-retro 的提案对照着看：**被 hook 提醒过、复盘里又出了事的坑，是升级的首选**；同一条在两个以上项目被碰到，按 LESSONS「怎么升级」考虑升级；命中很多但从没出过事的，多半是「触发」词太宽。
- 它只汇总，不写任何规则，照 LESSONS「只出提案」。

## 第 5 件：两份全局指令

- 选了「维持两份，由机器逐字比对」：每次自检都查 `~/.claude/CLAUDE.md` 和 `~/.codex/AGENTS.md` 里「跨项目沉淀」那一节是否一致。标题编号不同（「7.」）不算不一致；正文不一致时报 ✗，并指出从第几行开始不同。本机核对时两份正文是一致的。
- 没选「只存一份，Claude 那边用 `@` 导入」，原因有两个：
  - Codex 的 AGENTS.md 支不支持导入，没核实。
  - 改你本机的全局指令文件风险高。
- 以后想改成只存一份，再单独开 issue。

## 我替你做的默认决定（不满意直接改）

- 拒绝和先问的名单，按上面第 1 件的表。
- 脚本放在 agent-kit，没放 my-skills：这是跨项目的机器执行层，不是某个技能；而且这次读不到 my-skills。
- 第 3、4 件不重复造：launchd 和 Hermes 体检、会话复盘都交给 my-skills#30、#28。本仓库的 doctor 和每周汇总只做那两个不覆盖的部分。
- Claude 的自动记忆（auto memory）没替你关。自检会每次提示它的状态，关不关由你定。

tools/doctor.mjs             第 3、5 件：agent-kit 自检
tools/doctor.example.json    自检可选配置样例
tools/weekly-review.mjs      第 4 件：每周整理输入
tests/                       node:test 测试：node --test tests/*.test.mjs
