# 机器执行层：权限规则、hook、本机体检、每周汇总

来由：[2026-11-05 最佳实践对照报告](research/2026-11-05-best-practices.md)的结论是：「写给人和模型读的规矩」已经够严，缺的是「到了关键时刻机器一定会执行」的那一层。这里把报告里的 5 件事落成可安装的文件。

> 术语：
> - **hook**：Claude Code / Codex 在固定时刻（这里是「执行命令或改文件之前」）一定会跑的小脚本，不靠模型自觉。
> - **权限规则**：设置文件里的一行，写明哪类命令「先问我」。
> - **状态目录**：本机存提醒日志、体检报告的地方。macOS 上是 `~/Library/Application Support/agent-kit/`，不放 `/tmp`（G-01）。

## 一次装好（在本机终端里，约 2 分钟）

这个 PR 合并、主目录拉齐后，在 agent-kit 目录里依次跑：

```bash
node tools/install.mjs
```

先看预览，它会列出要改哪几个文件、加什么，**这一步不写任何文件**。确认没问题再跑：

```bash
node tools/install.mjs --apply
```

装完后，**新开**的 Claude Code / Codex 会话才生效。Codex 第一次可能会请你确认是否信任这两个 hook（未实测）。最后核对一遍：

```bash
node tools/doctor.mjs
```

- 会改的文件：
  - `~/.claude/settings.json`：加「先问」规则和 2 个 hook。
  - `~/.codex/hooks.json`：加 2 个 hook。
  - `~/.codex/rules/agent-kit.rules`：Codex 的「先问」规则。
- 每个文件写之前都备份成 `原文件名.bak-agent-kit-<时间>`。你原有的设置和 hook 原样保留。
- 装之前会先让两个 hook 各跑一次自检，没通过就什么都不改。
- 卸载：`node tools/install.mjs --uninstall --apply`，只去掉 agent-kit 加的东西。
- 只装一边：加 `--only claude` 或 `--only codex`。

## 第 1 件：不可逆操作，机器把关

| 操作 | Claude Code | Codex |
|---|---|---|
| 强推到 main/master（含 `--force-with-lease`、`+main`），或删除远端 main/master | **直接拒绝**（hook `hooks/guard-git.mjs`） | **直接拒绝**（同一个 hook） |
| `gh pr merge` | 先问你 | 先问你 |
| 推 main/master（`git push origin main`） | 先问你 | 先问你 |
| 强推分支（`-f` / `--force`） | 先问你 | 先问你，`--force` 写在最前面时才问到，见下 |
| 删除远端分支、`git reset --hard`、`git clean`、`git branch -D`、`git stash drop/clear` | 先问你 | 先问你 |
| `--force-with-lease` 推自己的分支 | 放行（《工程流程》第 5 节第 3 步允许） | 放行 |

- 规则文件：
  - Claude：[config/claude-permissions.json](../config/claude-permissions.json)。官方文档写明这类规则在自动模式下也会弹窗，`cd x && git clean -f` 这样拼在一起的命令也会问。
  - Codex：[config/codex/agent-kit.rules](../config/codex/agent-kit.rules)。
- 已核实：
  - Codex 规则已用 Codex 0.166.0 的 `codex execpolicy check` 实测。该问的会问，`--force-with-lease` 推分支、推普通分支不问。
  - guard-git 有二十多个命令样例的测试（`tests/guard-git.test.mjs`）。
- 没核实：没在真的 Claude Code 里实装跑过（云端会话改不到你本机的设置）。**装完请验一次**：在任意仓库里让 Claude 执行 `git push --force origin main`，应该看到「已拦下」，命令不会真的执行。
- 已知漏洞：
  - Codex 的规则只认开头几个词，`git push origin feature --force` 这种把 `--force` 写在最后的不会问。
  - `git -C 其他目录 push origin main` 这种写法，两边的「先问」规则都认不出来。但只要带强推、推的是 main，hook 照样拒绝。
  - **Hermes 不受这套约束**：它的派单靠什么兜底，要你另外定。

## 第 2 件：LESSONS 按关键词提醒

- LESSONS 每条 G-xx 末尾新加了一行「触发：」，写的是碰到这条坑时命令或代码里会出现的词。
- hook [hooks/lessons-remind.mjs](../hooks/lessons-remind.mjs) 在执行命令、改文件之前比对这些词，命中就把那条坑的标题和「正确做法」的第一句提示给模型。例如命令里有 `launchctl` 时，会提示 G-05 和 G-18。
- 它只提醒、从不拦截；同一会话里同一条只提醒一次。
- 每次命中都记一行到状态目录的 `lessons-hits.jsonl`，第 4 件的每周汇总会统计「哪条坑被碰到几次、在哪些项目」。
- 「触发」词怎么写，见 LESSONS 开头「怎么写」。词太宽会天天误报，这时就收窄。G-09（界面改动）想不出可靠的词，写了「无」。

## 第 3 件：本机体检

```bash
node tools/doctor.mjs
```

结果打在屏幕上，同时存一份报告到状态目录的 `doctor/` 下。报告第一行是开始时间，最后一行是 `exit N`（G-12 的写法），最多保留 60 份。有 ✗ 时退出码为 1。

不用配置就会查这些：

- Claude、Codex 的「先问」规则和 2 个 hook 装没装；两个 hook 能不能真的跑起来（hook 坏了默认放行，平时看不出来）。
- 两份全局指令里「跨项目沉淀」那一节是否逐字一致（第 5 件）。
- Claude 自动记忆开没开。
- 近 7 天哪些坑被提醒过。

**配置后**还能查下面这些。先复制 [tools/doctor.example.json](../tools/doctor.example.json) 到 `~/Library/Application Support/agent-kit/doctor.json`，按本机实际改：

| 配置项 | 查什么 | 对应的坑 |
|---|---|---|
| `launchd` | 每个任务装没装、常驻服务在不在跑、上次退出码、错误日志是否比正常日志新 | G-05、G-18 |
| `logs` | 长任务日志最后一行是不是 `exit N`；太久没更新 | G-12 |
| 自动 | 最近 24 小时重启过就报出来，并列出没在跑的常驻服务 | G-12 |
| `repos` | 本地 main 有没有没推的提交（别的会话留下的） | 《工程流程》5.1 |
| `commands` | 自定义命令，例如 Hermes 定时任务未处理的失败记录 | G-14 |

- 你本机 launchd 任务的名字，可以用 `launchctl list | grep -v com.apple` 查。
- Hermes 那条放在样例的 `commands_样例_待核实` 里，没有启用。原因是我没见过 `hermes cron incidents` 的真实输出，判断规则得在本机看过输出后再填。不能写成「有输出就算有问题」，G-14 的误报就是这么来的。

**定时跑（要你定）**：我建议用 Hermes 的定时任务，或者 Claude 桌面版的定时任务，每天跑一次，让它「有 ⚠ 或 ✗ 就把那几行发给我，全是 ✓ 就不说话」。不建议用 launchd：agent-kit 放在「文稿」目录下，launchd 直接启动的程序读不了「文稿」（G-05）。体检遇到这种情况会报「没有权限读取」，不会假装正常。

## 第 4 件：每周汇总 + 会话复盘试点

```bash
node tools/weekly-review.mjs
```

它把三样东西汇成一份 Markdown，存到状态目录的 `weekly/<日期>.md`，并打印文件路径：

1. 本机体检。
2. 近 7 天坑提醒命中统计。
3. 如果装了 sheal：近 7 天的工作摘要和花费。

它只汇总、不下结论，也不写任何规则。每周整理时，让 Claude 读这个文件出提案，照 LESSONS「只出提案」。

**sheal 试点（4 周）**：

```bash
npm install -g @liwala/sheal
```

- 只用 `sheal digest`、`sheal cost`，以及在某个项目里单独跑 `sheal retro`。我在断网的环境下实测过 0.3.0 版：`digest` 和 `retro` 都能照常出结果，说明是纯本地分析。
- **不用**这几个，它们会把会话内容发给模型或第三方，或把数据推到远端：
  - `--enrich`
  - `--agent`
  - `--slack`
  - `sheal ask`
  - `sheal backup`
- **不用** `sheal learn` 和 `sheal rules`。那是另一套「教训库」，规则会写进 AGENTS.md，会绕开 LESSONS 的批准制。
- 4 周后看效果，满足两条才继续：
  - 至少带出 1 条可以提案的新坑或升级。
  - 每周看这份材料不超过 15 分钟。
- 达不到就卸载：`npm uninstall -g @liwala/sheal`。卸载后汇总里第 3 部分会自动写「跳过」。

## 第 5 件：两份全局指令

- 选了「维持两份，由机器逐字比对」：每次体检都会查 `~/.claude/CLAUDE.md` 和 `~/.codex/AGENTS.md` 里「跨项目沉淀」那一节是否一致。不一致时报 ✗，并指出从第几行开始不同。
- 没选「只存一份，Claude 那边用 `@` 导入」，原因有两个：
  - Codex 的 AGENTS.md 支不支持导入，没核实。
  - 改你本机的全局指令文件风险高，这个云端会话也改不到。
- 以后想改成只存一份，再单独开 issue。

## 我替你做的默认决定（不满意直接改）

- 拒绝和先问的名单，按上面第 1 件的表。
- 脚本放在 agent-kit，没放 my-skills：这是跨项目的机器执行层，不是某个技能；而且 my-skills 这次读不到。
- 体检的 Hermes 检查先不启用，等你在本机看过输出再填。
- 定时跑体检不用 launchd，原因见第 3 件。具体用 Hermes 还是 Claude 桌面版，由你定。
- Claude 的自动记忆（auto memory）没替你关。体检会每次提示它的状态，关不关由你定。

```
config/codex/agent-kit.rules     第 1 件：Codex 的「先问」规则

tools/doctor.mjs             第 3、5 件：本机体检
tools/doctor.example.json    体检配置样例
tools/weekly-review.mjs      第 4 件：每周整理输入
tests/                       node:test 测试：node --test tests/*.test.mjs
```
