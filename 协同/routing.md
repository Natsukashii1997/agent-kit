# 场景路由：遇到什么事，用哪个模式

默认用**单 Agent 加现有 Skill**直接做。只有当第二个角色能带来原 Agent 没有的独立判断、不同的执行条件或独立证据时，才进入协同模式（V1.0 第 5 节五个准入判据）。争议的是一个谁都没拿到数据的事实问题时，先去取证，不要多叫几个 Agent 来讨论。

两份全局指令第 1 节指向本文。各模式的主 Skill 写的是自己的边界；本文只回答「该去哪个模式」。2026-11-27 从 multi-agent 并入 agent-kit；文中 V1.0、修订表、候选卡等设计文件留在 multi-agent 归档仓库（`https://github.com/Natsukashii1997/multi-agent`，`docs/design/`、`docs/candidates.md`）。

## 3. 其余六个场景不单独成模式

| 类别 | 场景 | 怎么处理 |
|---|---|---|
| 模式变体 | #03 需求澄清、PRD；#06 体验方案探索；#10 UI 验收 | 默认单 Agent。#06 的界面文案和交互，Claude 先做一版，可请 Gemini 4 Neon 当顾问改一遍（只改几个字的不用），改动由 Claude 对照功能实际怎么用核实后采纳。#03 碰到重大前提时转 MA-01；#06 方案差异大、要比较时转 MA-04；#10 有争议时转 MA-03（UI 自检照 ui-system 规则） |
| 触发条件 | #13 同一问题两次修复失败 | 不是模式，是检查节点（见 `thinking-review` 第 1 节）。失败暴露的是根因判断错了，走 MA-06；是重大前提变了，走 MA-01 |
| 不该触发 | #15 日常巡检、三报；#16 Skill/知识整理、文案 | 单 Agent 或单 Hermes。只有高风险成果才调用 MA-01 或 MA-03 |

## 4. 一个任务串几个模式

一个任务可以在不同阶段用不同模式，**不为组合另建模式或 Skill**（V1.0 第 7.3 节）。例如：

- 复杂产品从决策到上线：MA-01 定方向 → 单 Agent 开发 → 必要时 MA-03 独立验证 → MA-02 审查收口 → 常浩决定合并。
- 长期数字分身项目：MA-05 由 Hermes 委派 → Claude 执行 → 按风险走 MA-02 或 MA-03。

## 5. 停止与降级

- 达到契约里的退出条件就结束，不以「还可以多审一轮」为理由继续。
- 后续交付已经常规化、反复审查没有新信息时，降回单 Agent。
- 选定的 Agent 不可用（`node tools/probe-agents.mjs` 显示「不可用」或「未核实」）时，按契约暂停或换一个满足独立性的验证方，不悄悄降级成自测。各 Agent 的长期档案见 [agent-profile.md](agent-profile.md)。
